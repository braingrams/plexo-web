# Plexo Web

Next.js dashboard for the Plexo builder — templates, publishing, AI generation (BYOK and system AI), and billing. Consumes `@charisol/plexo-sdk` for the actual drag-and-drop editor.

## Setup

```bash
npm install
cp .env.example .env   # fill in real values, see below
npm run db:generate
npx prisma db push     # applies schema.prisma to your database
npm run dev
```

`npm run build` also runs `npm install @charisol/plexo-sdk@latest` first, so the SDK is always pulled at its latest published version at build time.

## Environment variables

See `.env.example` for the full list with inline comments. Most are self-explanatory (Neon Postgres URLs, Better Auth secret, Maildrip transactional email). Two areas need more than a value pasted in:

### AI (BYOK)

`AI_KEY_ENCRYPTION_SECRET` — any random 32-byte value (base64 is fine). Used to encrypt each account's own AI provider key (`ApiKey.aiApiKey`) at rest. **Rotating this invalidates every previously-stored BYOK key** — there's no re-encryption path across secrets, only `npm run ai:encrypt-keys`, which migrates legacy plaintext rows once.

### Host-Managed AI Access (Ultra plan only)

By default an account's AI requests are paid for either by Plexo's own credit ledger (System AI) or by a provider key the account supplies itself (BYOK). **Host-Managed** is a third mode for an embedding host application (like Maildrip) that wants to own AI authorization and billing for its *own* end users itself — every AI action in the builder is authorized and charged against the host's own credit system instead of Plexo's, via a webhook Plexo calls. It's gated to the **Ultra** plan (`lib/subscription.ts`'s `hostManagedAiEnabled`) since it hands a host app control over every AI request Plexo would otherwise meter/bill itself.

This is not something Plexo issues you — **the host generates its own webhook secret** and registers it on both sides, the same way you'd set up e.g. a GitHub webhook secret. Steps, in order:

1. **Generate a random secret** — anything long and unguessable works:
   ```bash
   openssl rand -hex 32
   # or
   node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
   ```
2. **Implement two endpoints on your own backend**, both under one base URL of your choosing:
   - `POST {yourWebhookUrl}/ai-authorize` — called before every AI generation, must respond `{ "allowed": true }` or `{ "allowed": false, "reason": "..." }` (the `reason` is shown to the end user).
   - `POST {yourWebhookUrl}/ai-charge` — called after a successful generation to actually charge the user; respond with any 2xx to acknowledge (body is not otherwise checked). Called with the same `requestId` as the matching `ai-authorize` call, retried a few times on failure — **deduplicate on `requestId`** so a retry never double-charges.

   Both requests are JSON POSTs with body:
   ```json
   {
     "externalUserId": "the host's own id for the end user driving the builder",
     "actionMode": "edit_element | edit_layout | generate_layout",
     "tier": "BASIC | MEDIUM | HIGH",
     "requestId": "uuid, stable across the authorize+charge pair for one generation",
     "usage": { "inputTokens": 123, "outputTokens": 456 }
   }
   ```
   (`usage` is only present on `ai-charge`.) Plexo never sends a cost — your endpoint owns the entire pricing/credit model; `actionMode`/`tier` are all it gives you to price the action.

3. **Verify every request's signature** before trusting it. Each request carries:
   - `x-plexo-timestamp` — ms epoch the request was sent
   - `x-plexo-signature` — hex HMAC-SHA256 of `` `${timestamp}.${rawRequestBody}` `` under your secret

   Reject the request if the signature doesn't match (recompute it yourself, don't trust anything in the body) or if `timestamp` is more than 5 minutes old/in the future (replay protection). Sign over the *raw* request bytes, not a re-serialized copy of the parsed JSON — the two aren't guaranteed to match byte-for-byte.
4. **Register the webhook** for the relevant API key in the Plexo dashboard → Settings → pick the key → set **AI Access Mode** to **Host-Managed**, then fill in your webhook base URL and paste the same secret from step 1 into **Webhook Signing Secret**. This option is only selectable on an Ultra-plan account.
5. **Set the identical secret value** in your own backend's environment/config so your `ai-authorize`/`ai-charge` handlers can recompute the same signature. There's nothing to copy *from* Plexo — the value only ever needs to match between the two places you put it (your server's env and the Plexo dashboard field), it isn't shown or generated by Plexo.

Once configured: the account's AI requests skip Plexo's own credit ledger entirely (no BYOK key needed, no System AI credits charged) and instead authorize/settle against your webhook. If your webhook is unreachable or times out, the request is **denied**, never silently allowed through — a host outage can never turn into unmetered AI usage. If the account is later downgraded off Ultra, Host-Managed requests are blocked (403) until it's back on Ultra or the mode is switched back to System AI/BYOK — it does not silently fall back to unmetered System AI billing.

### Phase 2 billing setup (Stripe + system AI credits)

This is the part that can't be automated — it needs your own Stripe account and provider credentials. Manual steps, in order:

1. **Create a Stripe account** (test mode to start). Get your secret key from the Stripe Dashboard → Developers → API keys, and set `STRIPE_SECRET_KEY`.
2. **Create Products/Prices in Stripe** for:
   - The `PRO` and `ULTRA` subscription plans (recurring, monthly) → set `STRIPE_PRICE_PRO` / `STRIPE_PRICE_ULTRA` to the resulting Price IDs.
   - Three one-off credit top-up packs (small/medium/large — amounts are up to you, see `lib/credits/catalog.ts` for the credit amounts each pack currently grants) → set `STRIPE_PRICE_TOPUP_SMALL` / `STRIPE_PRICE_TOPUP_MEDIUM` / `STRIPE_PRICE_TOPUP_LARGE`.
3. **Register the webhook endpoint** at `/api/webhooks/stripe`:
   - Production: add the endpoint in the Stripe Dashboard → Developers → Webhooks, subscribed to `checkout.session.completed`, `customer.subscription.created`, `customer.subscription.updated`, `customer.subscription.deleted`. Copy the signing secret into `STRIPE_WEBHOOK_SECRET`.
   - Local dev: run `stripe listen --forward-to localhost:3000/api/webhooks/stripe` (Stripe CLI) and use the signing secret it prints.
4. **Provide a system AI provider key** — this is Plexo's *own* provider account, used to serve AI requests for accounts that haven't configured their own BYOK key. Set `SYSTEM_AI_PROVIDER` (one of `anthropic_claude` / `openai` / `google_gemini`) and the matching `SYSTEM_AI_KEY_*` var. You can provision all three `SYSTEM_AI_KEY_*` vars at once — switching `SYSTEM_AI_PROVIDER` later is then just an env change, no redeploy of secrets, no code change.
5. **Sanity-check the numbers before real money is involved**:
   - `lib/credits/pricing.ts`'s `MODEL_PRICING` — the Anthropic row is real published pricing; the OpenAI/Gemini rows are placeholders and should be checked against each provider's actual billing page.
   - `CREDIT_USD_VALUE` (default `0.001`, i.e. 1000 credits = $1) and the monthly allowances in `lib/subscription.ts`'s `PLAN_MONTHLY_CREDITS` — adjust to whatever margin you want before launch.

Once configured: accounts without a BYOK key use system AI automatically, billed against their credit balance (monthly allowance, reset — not rolled over — every 30 days, plus any purchased top-ups, which never expire). Accounts with a BYOK key are unaffected and never touch credits.
